# 传统术数顾问 Skill 设计规格

日期：2026-09-16  
状态：待用户书面审查  
第一版范围：六爻占问，以《增删卜易》为唯一主要知识来源

## 1. 目标

建立一个安装在 Codex 全局技能目录中的 `traditional-divination-skill`。用户以后只需用自然语言提出“算命、起卦、看看某件事”等请求，Codex 即可自动识别并加载该 Skill。用户不需要记忆 Skill 名称、斜杠命令或六爻术语，只需回答逐项提出的必要问题。

第一版完成以下闭环：

1. 识别传统占问意图。
2. 把宽泛问题整理为一件可占问的具体事项。
3. 接受用户自行摇卦的六次结果，或在用户明确授权后随机起卦。
4. 可靠计算本卦、动爻和变卦。
5. 按《增删卜易》可追溯的方法解释卦象。
6. 给出传统解释、现实行动建议、信息缺口和不确定性。
7. 防止把传统占问包装成科学预测、医疗诊断、法律意见或投资保证。

## 2. 非目标

第一版不实现以下内容：

- 八字、紫微斗数、梅花易数、奇门遁甲、六壬或太乙排盘。
- 保存用户的生日、出生地点、卦例或个人档案。
- 自动读取聊天记录、联系人或其他私人数据。
- 预测彩票、赌博结果或保证投资收益。
- 用卦象判断疾病、停药、用药剂量或是否需要就医。
- 把《周易》决策框架、《黄帝内经》、托尔斯泰或经济史书籍混入六爻判断规则。
- 宣称传统术数已经获得现代科学验证。

## 3. 架构选择

第一版采用单一、边界清楚的 Skill，而不是立即建立大型套件。

```text
D:\Codex\skills\traditional-divination-skill\
├── SKILL.md
├── agents\openai.yaml
├── scripts\
│   ├── cast_coins.py
│   └── derive_hexagram.py
├── references\
│   ├── interaction-flow.md
│   ├── source-methods.md
│   ├── interpretation-format.md
│   ├── safety-and-uncertainty.md
│   └── source-audit.md
├── assets\
│   └── hexagram-map.json
└── evals\
    └── traditional-divination.eval.md
```

选择单一 Skill 的原因：第一版只有“六爻占问”这一条主要工作流，共享同一套输入、卦象计算和解释流程。八字、紫微等加入后才拆成多个独立 Skill，并在最上层增加 `personal-wisdom-skill` 路由器。

## 4. 自动触发设计

Skill 描述应覆盖以下明确意图：

- 算命、占卜、问卦、起卦、六爻；
- 看感情、事业、考试、求职、合作、出行等具体事件走向；
- 用户提供六次硬币结果、阴阳爻或本卦/变卦；
- 用户明确要求用传统术数分析。

近邻负例必须写入路由边界：

- “解释《周易》某一段”属于经典阅读，不自动起卦；
- “根据出生时间看八字”提示该能力尚未安装，不拿六爻代替；
- “胸口痛是不是有问题”属于医疗问题，不起卦；
- “帮我决定买哪只股票并保证赚钱”不得用卦象替代金融分析；
- 普通的概率题、随机数需求或硬币模拟不触发术数解释。

自动触发依赖 Codex 的 Skill 发现机制。正常情况下用户无需输入 `/traditional-divination-skill`；显式名称仅作为故障时的备用入口。

## 5. 用户交互

### 5.1 最简入口

用户可以只说：

> 帮我算一下最近的感情。

Skill 随后一次只询问一个必要问题，避免一次要求填写长表格。

### 5.2 必要输入

第一版需要：

1. 一个具体问题；
2. 合理时间范围；
3. 六次摇卦结果，或随机起卦授权。

可选输入：背景、已经发生的关键事件、用户正在考虑的选项。

### 5.3 问题规范化

Skill 将“我以后会不会幸福”这类无边界问题收敛为可解释问题，例如：

> 未来三个月，我与目前交往对象的关系发展中，最需要注意什么？

不得把用户问题偷偷改成含义不同的问题。规范化结果应先展示给用户；轻微措辞整理不需要反复确认，实质改变对象、时间或目标时必须确认。

### 5.4 起卦方式

支持两种方式：

- 用户摇卦：从初爻到上爻依次提供六次结果；
- 程序随机：只有在用户明确说“你帮我随机起卦”等同意语句后运行。

随机脚本必须输出原始六次结果、生成时间和转换后的爻，保证结果可以复核。不得在看到解释不理想后重新随机。

## 6. 确定性计算

`derive_hexagram.py` 负责确定性部分，不让语言模型心算：

1. 验证恰好有六爻且顺序明确为初爻到上爻；
2. 接受传统三钱数值 6、7、8、9；
3. 区分老阴、少阳、少阴、老阳；
4. 计算下卦、上卦、本卦、动爻和变卦；
5. 从受版本控制的 `hexagram-map.json` 读取六十四卦映射；
6. 输出机器可读 JSON 和人类可读摘要；
7. 输入不合法时停止，不猜测缺失爻。

第一版不自行计算完整纳甲、月建、日辰、旬空、六神与应期。只有在其算法来源和历法实现经过独立验证后，才作为后续小版本加入。第一版的解释范围必须与实际计算能力一致，不能假装已经完成专业排盘。

## 7. 书源与仓颉蒸馏

### 7.1 试点来源

- 书名：《增删卜易》
- 传统署名：野鹤老人著，李文辉增删；具体身份和版本沿革在审计中如实标注
- 文本：选择可访问、可追溯的公版古籍文本
- 用途：接入日常问事工作流，因此输出倾向 pack/可组合能力
- 试点：是，只先处理这一部书

### 7.2 仓颉流程

严格按 `cangjie-skill v2.5` 执行：

1. 建立原文快照、版本说明和来源哈希；
2. Adler 整书理解，输出 `BOOK_OVERVIEW.md`；
3. 用户确认整书骨架；
4. 分别提取框架、原则、案例、反例和术语；
5. 对候选执行来源充分性、可执行性和任务增益三重验证；
6. 通过晋级门的能力才成为独立入口，其余保留在来源路由能力中；
7. 生成 R/I/A1/A2/E/B 能力卡；
8. 对触发、计算、解释和边界进行代表任务测试；
9. 使用编译器生成安装产物，不直接手改生成目录。

《卜筮正宗》将在第一版通过后作为第二来源，用于交叉校验和补足结构化规则，不在第一次试点中混入。

## 8. 输出契约

每次完整回答采用稳定结构：

1. **占问信息**：问题、时间范围、起卦方式；
2. **卦象结果**：六次原始结果、本卦、动爻、变卦；
3. **传统解释**：区分原书规则、当前推断和仍缺少的信息；
4. **现实建议**：用户现在可采取的低风险行动；
5. **不确定性**：说明传统术数不能保证事件结果；
6. **高风险提示**：涉及医疗、法律、财务或人身安全时，补充现实核验渠道。

不得只给“吉/凶”结论。解释必须说明条件、推理链和可能使判断失效的因素。

## 9. 隐私与安全

- 默认不把输入写入长期档案；
- 不要求真实姓名、身份证、联系方式或聊天记录；
- 不把用户的敏感问题发送给额外第三方服务；
- 不生成死亡日期、严重疾病结论或不可逆的人际指控；
- 不断言伴侣出轨、他人犯罪或存在恶意，只能表达为待核验假设；
- 对反复询问同一问题提示重复占问可能放大焦虑，不通过重复随机获得更满意答案；
- 如果用户表现出自伤、被害或严重心理危机迹象，停止术数解释并优先提供现实支持建议。

## 10. 测试与完成标准

### 10.1 自动测试

- 64 个静态卦象映射测试；
- 无动爻、单动爻、多动爻、六爻皆动测试；
- 爻序颠倒检测；
- 非法数值、少于或多于六次结果的拒绝测试；
- 固定随机种子仅用于测试，正式起卦使用系统安全随机源；
- JSON 输出结构测试。

### 10.2 Skill 触发测试

正例：算命、六爻、起卦、提供硬币结果。  
负例：普通读书解释、医疗症状、金融保证、八字请求、概率模拟。

### 10.3 内容测试

- 每个规则能够定位到书源；
- 引文长度符合仓颉限制；
- 合成示例明确标注，不冒充书中案例；
- 回答包含现实建议和不确定性；
- 不混用尚未实现的八字、紫微、奇门规则；
- 不声称科学准确率。

### 10.4 完成定义

只有同时满足以下条件才算完成：

1. 仓颉 Bundle 和审计轨迹齐全；
2. 计算脚本自动测试通过；
3. Skill 格式验证通过；
4. 安全扫描通过；
5. 代表性端到端问卦测试通过；
6. 安装到 `D:\Codex\skills\traditional-divination-skill`；
7. 新会话中自然语言触发测试成功。

## 11. 后续演进

第一版稳定后，每次只新增一个独立来源或方法：

1. 《卜筮正宗》交叉校验；
2. 《周易》经传阅读与决策模块；
3. 《江湖丛谈》骗局识别模块；
4. 八字模块；
5. 紫微斗数模块；
6. 《黄帝内经》传统医学思想模块；
7. 《大分流》《失控》、托尔斯泰等非术数模块；
8. 最后建立 `personal-wisdom-skill`，按用户意图自动路由已验证模块。

不同模块共享的只有路由协议、输出标签和安全边界，不共享各自的推断规则。

## 12. 已决定事项

- 用户希望自然语言自动触发，不进行复杂操作；
- 第一版以六爻为核心；
- 用户只提供当前问题所需信息；
- 默认不永久保存个人数据；
- 使用真实古籍来源，不凭模型记忆蒸馏；
- 先完成一书试点，再扩展；
- 安装后由 Codex 自动发现和调用；
- 传统术数定位为文化与反思工具，不作科学保证。
